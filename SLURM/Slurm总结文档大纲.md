# Slurm 总结文档大纲

本文计划从入门理解、日常操作逐步展开到工作原理和优化。当前仅保存大纲，暂不编写正文。

注意：分区、计算节点、作业各有自己的状态体系；控制服务主要关注是否响应、主备角色和服务健康。

## 1. Slurm 是什么

- 解决什么问题：资源管理、任务排队、调度执行。
- Slurm 管什么，训练程序自己负责什么。

## 2. Slurm 与集群由什么组成

- 主控制节点、备用控制节点：`slurmctld`。
- 计算节点：`slurmd`，以及执行作业步骤的 `slurmstepd`。
- 登录／提交节点：用户操作入口。
- 可选记账服务：`slurmdbd` 和数据库。
- 共享存储、网络、认证等配套设施。
- 一台机器可以承担多个角色。

## 3. 核心概念及其关系

- 分区（Partition）：节点范围和使用规则。
- 作业（Job）、作业步骤（Step）、任务进程（Task）。
- 节点、CPU 单位、内存、GPU。
- 一个节点属于多个分区时，如何统一管理资源。
- 账号（Account）、QoS、优先级的区别。

## 4. 各类状态及其含义

- 分区：`up`、`down`、`drain`、`inact`。
- 节点：`idle`、`mix`、`alloc`、`drng`、`drain`、`down` 等。
- 节点状态附加符号：例如 `*` 表示不响应。
- 作业：等待、运行、收尾、完成、失败、取消、超时等。
- 等待原因与状态的区别。
- 分区排空和节点排空的区别、相互影响。

## 5. 如何使用和管理 Slurm

- 从哪里发命令：登录节点、控制节点与客户端。
- 查询：`sinfo`、`squeue`、`scontrol show`、`sacct`。
- 提交和运行：`sbatch`、`salloc`、`srun`。
- 管理自己的作业：取消、暂停启动、解除等待。
- 管理员操作：维护分区、排空和恢复节点。
- 普通用户权限与管理员权限。

## 6. 如何申请资源和编写作业脚本

- 分区、节点数、task 数、每个 task 的 CPU 数。
- 内存、GPU、时间上限、输出日志。
- 默认值、命令行参数与脚本参数的优先关系。
- 指定节点、共享节点与独占节点。
- 申请资源、分配资源、实际使用资源的区别。

## 7. 一个作业从提交到结束的全过程

- 提交 → 检查请求 → 排队 → 调度 → 分配资源。
- 启动进程 → 执行 → 清理 → 释放资源 → 记录历史。
- 用一个简单示例串起各组件和命令。
- 本节作为全文的串联主线。

## 8. Slurm 的底层工作原理

- 客户端、控制服务、计算服务如何通信。
- 控制器如何维护节点和资源状态。
- 调度如何考虑资源、优先级与限制。
- 回填调度：利用空闲资源，又不延误已安排的作业。
- 进程管理、CPU 绑定和资源隔离。
- 认证、故障检测与主备接管。

## 9. Slurm 与 PyTorch 分布式训练

- 分配资源不等于自动实现并行训练。
- `srun`、`torchrun`、DDP 分别负责什么。
- GPU、训练进程、Slurm task 的对应关系。
- 多节点训练对代码、环境、数据和网络的要求。

## 10. 如何观察问题和寻找优化空间

- 为什么任务等待，为什么节点不响应。
- 为什么节点空闲，任务却无法启动。
- CPU、内存、GPU 申请量与实际用量是否匹配。
- 数据加载、存储、通信是否成为瓶颈。
- 分区规则、时间上限和调度策略是否合理。
- 从只读查询开始，区分现象、原因和改进措施。

## 11. 命令速查与常见误区

- 常用命令、关键输出字段。
- `sinfo` 看分区和节点，`squeue` 看作业。
- 一个 Job 不等于一个 Task。
- `alloc` 不等于硬件利用率高。
- 分区 `drain` 不会自动让节点变成 `drain`。
- `bash job.sh` 与 `sbatch job.sh` 的区别。
